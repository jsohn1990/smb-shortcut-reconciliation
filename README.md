# SMB Shortcut Reconciliation

## Overview

A collection of three Bash scripts developed to identify Windows `.lnk` shortcut files on a Linux-mounted SMB share, locate their possible original files or directories, and replace the shortcuts with Linux symbolic or hard links.

The scripts were developed to simplify file organization and address compatibility differences between Windows shortcuts and Linux filesystem links.

The workflow is deliberately divided into three stages to allow manual review before making filesystem changes or deleting shortcut files.

## Scripts

### 1. `01_shortcut_triage.sh` — Discovery and Matching

- Searches the mounted SMB share for `.lnk` files.
- Extracts shortcut basenames and escapes special characters for regular-expression matching.
- Searches for possible original files and directories.
- Records uniquely identified candidates in a pipe-delimited CSV file.
- Generates separate reports for ambiguous matches, missing originals, and filename discrepancies.

### 2. `02_link_generator.sh` — Link Creation

- Reads the matching results generated by the first script.
- Creates symbolic links for directories and hard links for regular files.
- Records successfully created links in separate CSV logs.
- Reports link-creation failures.

### 3. `03_shortcut_cleanup.sh` — Shortcut Removal

- Reads the shortcut records generated by the first script.
- Removes the corresponding `.lnk` files.
- Records successful deletions in a log.

## Requirements

- Linux with Bash
- GNU utilities including `find`, `sed`, `gawk`, and `coreutils`
- Access to an SMB share mounted within the Linux filesystem
- Appropriate filesystem permissions to create links and remove shortcut files

The scripts expect the share to be mounted at:

```bash
${HOME}/smb/${USER}
```

This path can be changed by modifying `base_dir` near the beginning of each script.

## Usage

Run the scripts individually in the following order:

1. Run `01_shortcut_triage.sh` and review the generated matching results and reports.
2. Run `02_link_generator.sh` only after confirming that the proposed matches are correct. Verify the resulting symbolic and hard links.
3. Run `03_shortcut_cleanup.sh` only after confirming that the replacement links were successfully created.

Intermediate files are stored in `.shortcut_files` within the mounted share. Each script maintains its own logging directory.

## Important Notes

- The scripts are intended for a specific file-management workflow, not as a general-purpose Windows shortcut parser.
- Matching is based on filenames rather than reading the actual targets stored inside `.lnk` files.
- Ambiguous matches require manual review.
- Hard links cannot span different filesystems and may be restricted by the underlying SMB filesystem.
- The cleanup script does not independently verify that replacement links were created. Manual verification is required before running it.
- The revised versions have not been fully retested as an integrated workflow.
